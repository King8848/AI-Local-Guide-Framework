# 熟客纯吃模式（Repeat Visitor Pure Food Mode）

> **发现日期**：2026-07-18  
> **触发会话**：长沙 2 天自驾纯吃（4 人，无预算，去过很多次）

---

## 模式定义

用户对目的地城市非常熟悉（去过多次），此行**唯一目的是吃**，不逛景点、不需要城市介绍、不需要酒店推荐。需要的是**深度本地美食推荐 + 严格避开网红店**。

---

## 触发条件

以下任一信号组合触发此模式：

| 信号 | 示例 |
|------|------|
| "去过很多次" | "去过很多次长沙了" |
| "主要去吃" / "纯吃" | "主要去吃当地特色，不玩" |
| "不要推荐网红店" | 明确拒绝网红/连锁 |
| "XX天 + 只吃" | "去玩两天，主要去吃" |
| 无景点需求 | 全程不提及任何景点/打卡点 |

---

## 模式特征

| 维度 | 常规旅行规划 | 熟客纯吃模式 |
|------|------------|------------|
| 城市介绍 | ✅ 必含 | ❌ 跳过（用户比你还熟） |
| 景点推荐 | ✅ 核心 | ❌ 完全不提 |
| 酒店推荐 | ✅ 需要 | ❌ 用户自己搞定 |
| 交通路线 | ✅ 需要 | ⚠️ 只提停车/片区移动建议 |
| 美食推荐 | ✅ 重点 | 🔴 **唯一重点，100%篇幅** |
| 网红店 | ⚠️ 避坑提及 | 🔴 **严格排除，不作为选项** |
| 攻略结构 | 行程+美食+景点+预算 | **纯美食 9 维度索引** |

---

## 执行流程

### Step 1：轻量 Re-ground（跳过城市介绍）

```
不是："长沙是湖南省会，有三千年的历史文化..."
而是："长沙，4人自驾，2天纯吃，不逛景点，没预算上限，不要网红店"
```

### Step 2：片区确认（关键！）

因为是纯吃，片区选择决定了整趟行程的效率：

- 提出 2-3 个美食片区的组合方案
- 每个片区说明"为什么这个片区适合纯吃"
- 让用户确认片区后，每个片区对应一天

### Step 3：美食调研（数据源链）

纯吃模式的数据需求极高，必须多源交叉验证：

| 优先级 | 数据源 | 用途 | 本次是否可用 |
|--------|--------|------|------------|
| 1 | 大众点评浏览器 | 餐厅评分/评价（最硬信号） | ❌ 被登录墙拦截 |
| 2 | 小红书浏览器 | 本地人种草/探店笔记 | ❌ 编码错误 |
| 3 | **Serper/search (hl:zh-cn)** | **中文深度搜索（最可靠）** | ✅ 主力，全部有效 |
| 4 | Firecrawl/scrape | 抓取搜索结果中的文章全文 | ✅ 辅助提取详情 |
| 5 | 知识库兜底 | 历史积累数据 | ⚠️ 仅作补充 |

**实践结论**：当大众点评和小红书都不可用时，Serper + Firecrawl 组合可以独立完成纯吃模式的深度调研。

### Step 4：9 维度全覆盖输出

必须覆盖完整的 9 大美食维度（见 `food-section-template.md`）：

1. 早餐全景
2. 面食宇宙
3. 硬菜大菜
4. 夜市/街头小吃
5. 酒水茶饮
6. 甜点糕点
7. 时令美食日历
8. 伴手礼食品
9. 美食文化笔记

### Step 5：输出结构

```
📅 Day 1：片区A（早餐 → 午餐 → 下午小吃 → 晚餐/夜宵）
📅 Day 2：片区B（同上结构）
🗺️ 9 维度美食索引（独立章节，方便查阅）
💰 预算估算
⚠️ 避坑
```

---

## 输出规范（纯吃模式专用）

### 必须有的
- 每家店 **"为什么推荐"** （排队王/本地人密度/开了多少年/独特口味）
- **片区步行可行性**（车停哪，走路吃）
- **自驾停车提示**（老城区停车极难）
- **人均价格**
- **时令标注**（7 月必须标注夏日限定）

### 不能有的
- 景点介绍
- 酒店推荐
- 网红店（哪怕提到了也要标注"已排除"）
- 城市历史文化段落
- "这是你第几次来"之类的废话

### 措辞
- "推荐的店"（不是"本地人常去的店"）
- "建议出发前用高德确认"
- "排队王" / "学生验证" / "老口子认可" 等有信息量的标签

## 本次实战验证（长沙 2026-07-18）

| 验证项 | 结果 |
|--------|------|
| Serper/search 作为唯一可用中文搜索源 | ✅ 完全胜任，返回 45+ 有效结果 |
| Firecrawl 抓取深度文章 | ✅ 提取详细店名/地址/人均/推荐菜 |
| 大众点评登录墙 | ❌ 确认无法绕过 |
| 小红书编码问题 | ❌ 确认无法绕过（utf-8 decode error） |
| 9 维度在一次规划中全覆盖 | ✅ 圆满完成 |
| 用户确认框架速度 | ✅ 2 轮确认即开始执行 |

## HTML 输出变体（纯吃模式专用）

纯吃模式的 HTML 与标准 4 标签页模板不同：

| 维度 | 标准旅行 HTML | 纯吃模式 HTML |
|------|-------------|-------------|
| 标签页 | 4 页（行程/攻略/预算/清单） | **3 页**（总览/D1/D2） |
| 地图位置 | 悬浮右下角浮窗 | **全页面 sticky 顶部** |
| 地图库 | MapLibre GL + OpenFreeMap | **纯 Leaflet + OSM 瓦片**（最稳定） |
| 卡片交互 | 点击展开详情 | **点击 flyTo 飞到店铺坐标** |
| 导航按钮 | Action Sheet 三选一 | **直接弹 confirm → 高德 / Apple Maps** |
| CDN | 模板用 `unpkg.com` | **必须换 `cdn.jsdelivr.net`** |

### HTML 构建要点

1. **CDN**：只用 `cdn.jsdelivr.net`，不用 `unpkg.com`（国内被墙）
2. **地图**：Leaflet 1.9.4 + OSM tile (`{s}.tile.openstreetmap.org`)，不引入 MapLibre GL（bridge 库加载不稳定）
3. **结构**：`DAYS[]` 数组驱动，每行一个餐厅对象 `{n, lat, lng, t:'bf'|'lu'|'sn'|'di'|'dr', tm, d, p}`
4. **配色**：深色主题，5 色编码（早餐橙/午餐红/小吃珊瑚/晚餐紫/酒水靛），emoji 圆点标记
5. **底部水印**：`position:fixed` 左下角淡雅文字
6. **预算**：每天底部自动汇总 `d.locs.reduce((s,l)=>s+(parseInt(l.p)||0),0)`

### 验证步骤

生成 HTML 后必须用 `browser_navigate` + `browser_console` 验证：
- 总览页：地图 + 信息卡 + 避坑提示 + 行程概览可点击
- D1/D2：timeline 卡片 + 地图标记 + 导航按钮可点击
- 无 JS errors（如果有 2+ 条空 message errors = CDN 加载失败）

## 常见坑（纯吃模式专用）

| 坑 | 对策 |
|----|------|
| 把熟客当游客——输出城市介绍/景点推荐 | 触发条件中任一信号命中即跳过城市介绍 |
| 忘了问自驾停车 | 默认老城区停车难，执行 Step 2 时主动提 |
| 网红店混入推荐列表 | 搜索 query 加 `非网红 -网红 -排队2小时`，输出时主动标注排除的网红店 |
| 时令信息缺失 | 强制搜索 `{城市} {月份} 时令 美食` |
| 夜生活被忽略 | 纯吃也要默认安排夜生活（年轻人的默认需求） |
| HTML 地图白屏/空页面 | CDN 用 `jsdelivr` 不用 `unpkg`；优先纯 Leaflet+OSM，不引入 MapLibre GL bridge |
