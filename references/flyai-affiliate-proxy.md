# FlyAI 推广者代理架构

> 2026-07-19 验证：开源项目中集成飞猪 API 的推广者模式设计。

---

## 场景

你是飞猪推广者，想在自己的开源 AI 旅行 Skill 中集成飞猪搜索/预订能力：

- **你的代理服务**持有 API Key，对外提供搜索接口
- **开源项目**只写调用逻辑，不暴露 Key
- **其他用户**通过你的代理调飞猪 API，预订酒店/度假商品你有佣金

---

## 推广流程

```
申请入驻 → 获取正式 API Key → 配置至 Skill → 用户购买 → 佣金归因 → 查看收益/提现
```

### 收益说明

| 项目 | 说明 |
|------|------|
| 收益来源 | 用户通过你的 Agent 预订飞猪商品所产生的佣金 |
| 支持分佣 | 酒店、度假类商品 |
| 暂不参与 | 交通类商品 |

---

## 架构设计

```
开源项目 (GitHub)
├── providers/
│   └── flyai-provider.md    ← 调用逻辑（无 key）
├── .env.example              ← 配置模板
└── proxy-server/             ← 代理服务端（可选）
    └── flyai-proxy.py        ← 持有 key，对外提供接口
```

### 两种使用方式

| 用户类型 | 方式 | 安全 |
|----------|------|------|
| **自己/高级用户** | 本地跑 CLI，`.env` 填 key | ✅ key 不暴露 |
| **普通用户** | 连你的代理服务 | ✅ key 在服务端 |

---

## 安全约束

- **禁止**将 `FLYAI_API_KEY` 硬编码在开源代码中
- **禁止**将 Key 暴露在前端/浏览器代码中
- **禁止**将 Key 提交到 Git 仓库
- Key 仅限服务器环境（CLI/代理）使用
