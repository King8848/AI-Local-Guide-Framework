> **事故来源**：2026-07-18 session `20260718_011948_ff6cd1`
> **模型**：LongCat-2.0（via longcat provider）
> **严重等级**：🔴 产品事故 — 旅游规划中回答了用户家乡的美食

## 事故复现

### 会话上下文

- 用户 invoked `/skill ai-local-friend 我想去旅游`

  - 目的地：四川川西（康定→新都桥→塔公→丹巴→四姑娘山）
  - 天数：7 天
  - 人数：3 人
  - 交通：自驾、夜班火车往返
- 模型已完成行程规划、酒店搜索、地图页面生成

### 事故链路

```
用户问"本地有什么美食"
    │
    ▼
模型跳过 Re-ground（应该先说：我们在规划川西行程）
    │
    ▼
"本地" 被歧义解析 → user-preferences 中"常驻南昌九龙湖"被激活
    │
    ▼
模型调用 FlyAI keyword-search → 查询南昌酒店/美食
    │
    ▼
输出南昌本地美食 → 与川西行程完全无关 ❌
```

## 根因分析

| # | 根因 | 详情 |
|---|------|------|
| 1 | **无强制 Re-ground** | ai-local-friend 工作流定义了"先 Re-ground"但未作为强制规则。LongCat-2.0 在长对话中跳过此步骤。 |
| 2 | **"本地" 一词歧义** | 在旅行规划中，"本地" = 目的地城市。但 user-preferences 中「常驻位置：南昌九龙湖」使模型倾向于"本地=家乡"。 |
| 3 | **用户偏好信息污染** | `user-preferences.md` 中记录了南昌信息（九龙湖、南昌美食），模型在全量上下文中被这些信息干扰。 |
| 4 | **LongCat-2.0 长对话不稳定** | 7 轮螺旋问询 + 酒店搜索 + 地图生成后，上下文窗口可能接近极限，模型开始丢失早期上下文。 |
| 5 | **缺少上下文校验层** | 技能中没有「每次输出前检查是否符合当前上下文」的强制步骤。 |

## 预防模式

### P1：强制 Re-ground（每次回答前）

```
1. 当前我服务的行程是什么？
   → 四川川西 7 天自驾，康定→新都桥→塔公→丹巴→四姑娘山，3 人

2. 用户这个问题在行程上下文中是什么意思？
   → "本地美食" = 川西沿途美食（康定/新都桥/丹巴/四姑娘山/成都）

3. 我的回答/搜索结果与行程一致吗？
   → ✅ 搜索 query 应包含"康定""新都桥""丹巴"等目的地城市名
```

**不通过检查，不输出、不调用 API。**

### P2：歧义词自动替换

| 用户说 | 在旅行规划中 = | 搜索 query 必须包含 |
|--------|---------------|-------------------|
| "本地" | 目的地城市 | `{city} 美食` |
| "这边" | 目的地城市 | `{city} 特色` |
| "附近" | 当天路线片区 | `{day_location} 附近` |
| "回去" | 返程 | `{home}→{destination} 返程` |

### P3：搜索 query 加目的地前缀

```
❌ flyai keyword-search --query "本地美食"
✅ flyai keyword-search --query "康定 特色美食"
✅ flyai keyword-search --query "新都桥 牦牛肉"
```

### P4：用户偏好文件加免责

在 `user-preferences.md` 开头和常驻位置旁标注：
> ⚠️ 本文件中的「常驻位置」仅用于判断出发地，不用于旅游目的地推荐。

### P5：模型选择

| 场景 | 推荐模型 | 原因 |
|------|---------|------|
| 长对话旅行规划（3+ 轮） | DeepSeek V4 Pro | 上下文窗口大、稳定性高 |
| 短对话测试（≤2 轮） | LongCat-2.0 | 快速迭代 |
| 代码/文档任务 | DeepSeek V4 Pro | 精准度高 |

## 上下文校验清单（每次回复前自检）

```
□ 我是否输出了 Re-ground？（告诉用户"我们正在规划 XX 的 XX 天行程"）
□ 我的回答是关于目的地城市的，不是用户家乡的？
□ 我调用的搜索关键词是否针对目的地？
□ 搜索"本地美食"时，query 是否明确包含了目的地城市名？
□ 如果用户偏好中有常驻位置信息，我是否确认了它在当前上下文中不适用？
```
