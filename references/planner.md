# Planner Engine — 行程规划模块

> 开源版本 — 通用行程规划框架

---

## 职责

根据用户约束生成完整行程方案。

---

## 输入

| 字段 | 类型 | 必需 | 说明 |
|------|------|------|------|
| destination | string | ✅ | 目的地城市 |
| days | number | ❌ | 天数（未提供时推荐） |
| style | string | ❌ | 旅行风格 |
| budget | object | ❌ | 预算范围 |
| travelers | object | ❌ | 出行人数和构成 |
| constraints | array | ❌ | 特殊需求 |

---

## 规划原则

### 选点原则

1. **一天一个主区域** — 减少交通时间
2. **一天只放一个重预约点** — 避免预约冲突
3. **第一天轻手** — 到达日不排满
4. **最后一天不跑远** — 方便返程
5. **长距离点避开节假日**
6. **户外点标记天气敏感**

### 删点原则

- 天数不够的远郊 → 删
- 节假日会爆的热门 → 删
- 重复类型的景点 → 删

**必须说明删了什么，为什么删。**

### 路线组织方式

模块化清单（非流水线）：

```
【必做】选 2-3 个
- [ ] [项目1] → [时段+理由]

【推荐】选 3-5 个
- [ ] [项目2] → [时段+理由]

【可选】有时间加
- [ ] [项目3]（[所需时间]）
```

---

## 执行步骤

| 步骤 | 操作 | 说明 |
|------|------|------|
| 1 | 抽硬约束 | 到达/回程时间 → 首/尾天安排 |
| 2 | 用户清单分组 | 城内轻松/预约组/远郊组/可路过组 |
| 3 | 删高风险点 | 说明原因 |
| 4 | 按区域重组 | 一天一个主区域 |
| 5 | 补吃饭 | 按当天区域给候选 |
| 6 | 补交通/营业时间 | 关键查询 |
| 7 | 写参考文档 | 先说结论 → 每天安排 → 敏感点 → 餐厅候选 → 删了什么 → 提前订什么 |

---

## 输出格式

严格按照 `schema/trip-data.json` 的 TripData Schema 输出。

---

## 城市等级体系

用于预算系数调整。

| 等级 | 特征 | 住宿系数 | 餐饮系数 |
|------|------|---------|---------|
| T1 — 一线 | 住宿贵、交通便利 | ×1.5 | ×1.3 |
| T2 — 新一线/省会 | 住宿中等、性价比高 | ×1.0 | ×1.0 |
| T3 — 二三线 | 住宿便宜、景点集中 | ×0.7 | ×0.8 |
| T4 — 县城/乡镇 | 住宿很便宜、需包车 | ×0.5 | ×0.7 |

---

## 禁止

- 编造实时信息
- 一股脑把用户清单全塞进去
- 为了名店扭曲整体路线

---

## Boundaries

**开源版**：基础规划（1-7天）+ 输出标准 + 城市知识包

**高级版（商业）**：实时数据接入 / 动态调整 / 多城市联动 / 高级模板引擎
