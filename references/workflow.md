# User Interaction Workflow

> 开源版本 — 用户交互工作流规范

---

## 4-Step Format

所有需要用户决策的提问统一遵循：**Re-ground → Simplify → Recommend → Options**

| Step | Action | Why |
|------|--------|-----|
| **Re-ground** | 告诉用户"你在哪" | 用户可能 20 分钟没看屏幕 |
| **Simplify** | 用大白话说清在问什么 | 不用术语 |
| **Recommend** | 给一个明确推荐 + 理由 | 降低决策负担 |
| **Options** | 2–4 个可点击选项 | label 自解释 |

---

## 场景示例

### 场景 1：信息不足

用户说"帮我做个东京行程"：

```
Re-ground:  行程规划, Step 1: 基本信息
Simplify:   先搞清楚几件事，才能排行程。
Recommend:  建议先告诉我日期和酒店，其他我可以帮你选。

Q1 出行信息:
  A) 我发截图 — 机票/酒店截图丢过来，我自己提取
  B) 我打字说 — 告诉我日期、酒店、想去的地方

Q2 人数和节奏:
  A) 两人，能走 — 标准节奏
  B) 带老人/小孩 — 放慢节奏
  C) 一个人 — 自由安排
```

### 场景 2：路线取舍

```
Re-ground:  行程规划, 路线取舍
Simplify:   4 天放不下 12 个点，需要砍掉几个。
Recommend:  建议砍远郊，天数短来回浪费半天。

Options:
  A) 按你说的砍远郊（推荐）
  B) 我一定要去箱根，砍别的
  C) 让我看看完整清单再决定
```

### 场景 3：餐厅风格

```
Re-ground:  行程规划, Day 1 晚餐
Simplify:   第一晚刚到东京，选什么风格的饭。
Recommend:  建议选落地型，离酒店近、出餐稳。

Options:
  A) 落地型 — 离酒店近 + 喝一杯（推荐）
  B) 打卡型 — 网红店 + 老洋食
  C) 我有别的想法
```

## 关键原则

### Smart Skip

用户指令已包含的信息，跳过对应问题。

用户说了"两个人、不要浅草寺、喜欢吃"，就别再问这三个。

### 问题合并

没有依赖关系的问题，合并到一次交互。能一次解决的不拆成三次。

### 不问就默认

非必要的探索性问题，用户没提就替他决定。

### 严格区分 Will 和 Is

- "计划" / "接下来会" — 还没执行
- "已经" — 已完成

---

## 反模式

| Anti-pattern | Problem | Fix |
|--------------|---------|-----|
| 没有 Re-ground 直接问 | 用户迷失 | 先定位 |
| 列选项没推荐 | 选择瘫痪 | 给推荐 |
| 要求打字回答 | 摩擦大 | 提供选项 |
| 问了已答过的 | 浪费时间 | Smart skip |
| 未完成说已完成 | 信任破裂 | 分清 will/is |

---

## 禁止

- 连续问十几个问题
- 没有 Re-ground 直接问
- 把未执行的说成已完成
